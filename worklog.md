- Family B (app-side): browser Notification API while tab open (free, no SW needed), SSE replacing 10s poll (sub-second, free, right-sized for ~50 concurrent), Web Push via VAPID + service worker (free forever, no third party, works with tab closed; Android/desktop native, iOS requires PWA add-to-home-screen on 16.4+), PWA install = free "own app" without app store, wall-display red-banner mode as floor-wide broadcast.
- Key integration insight: current webhook POSTs DischargeFlow-proprietary JSON; each IM channel needs its own payload shape (ntfy: plain body + Title/Priority/Click headers; Slack: {"text"} or blocks; Teams: Adaptive Card; Telegram: bot API sendMessage w/ chat_id — NOT a bare webhook URL). Proposed per-channel adapter layer (channel enum on AlarmRule / per-user channel prefs) in alarms.ts — preserves the "webhook for now, swappable later" promise.
- PHI flag raised: current webhook payload ships patient name + MRN + doctor — unsafe for external IM channels without BAA. Proposed PHI-lite payload mode for external channels (room/floor/stage/minutes-over only).
- Fatigue guardrails proposed on top of existing dedupeKeys: repeat cooldown, max repeats before escalation, quiet hours, per-user daily digest.
- Recommended ladder (all $0): L0 wall-display banner → L1 in-app bell + browser Notification API + SSE upgrade → L2 Web Push VAPID for closed-tab → L3 per-category IM channel (nurses → ntfy floor topics; physicians → Telegram/Teams; finance → Teams/Slack) → L4 unacked escalation (30 min → charge nurse, 60 min → house supervisor, matching original design). All layers deep-link to the case with one-tap ack; add Notification.ackedAt → future MTTA (mean time to acknowledge) stat in the Analysis tab.
